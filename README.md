# platform-mail · 聚合消息平台邮箱接入

面向「聚合消息工作台」（SPEC 1.0，平台 key 固定为 `mail`）的邮箱接入包：定时收集邮箱中的候选人回复消息，按统一格式落盘，并由适配器转换为平台候选人卡片。

## 目录结构

```
platform-mail/
├── platform-mail/
│   └── SKILL.md          # 平台技能：登录 → 读取新消息 → 回复消息（5 节规范）
├── platforms/
│   └── mail.py           # 桥服务适配器：data/messages/mail.md → 候选人卡片
└── data/
    ├── messages/
    │   └── mail.md       # 消息记录（技能唯一输出，仓库内为空模板）
    └── mail.json         # 零代码兜底数据（仓库内为空模板）
```

## 适用邮箱与通道

- 飞书企业邮箱：通过 `lark-cli mail` 以当前用户身份访问，身份由平台注入，技能内不保存任何密码。
- Gmail（任意 Gmail 账号通用）：通过浏览器自动化打开 mail.google.com 收集，首次登录或出现验证码时由用户本人接管完成，AI 不代填密码；登录态有效时每日自动读取未读。
- 其他网页邮箱（QQ / 163 / Outlook 等）：按 SKILL.md「登录」节的通用浏览器步骤替换入口，其余读取、记录、回复逻辑不变。

## 安装到平台工程

1. `platforms/mail.py` 复制到平台工程 `platforms/` 目录，文件名保持 `mail.py`。
2. `platform-mail/` 目录放入平台工程的技能目录。
3. `data/` 合并到平台工程 `data/` 目录。
4. 刷新桥服务（支持热重载），访问 `http://127.0.0.1:8790/api/ping`，确认返回中包含 `mail` 平台、设置页显示「邮箱 已接入」。

## 数据链路

```
邮箱收件箱
   │  platform-mail 技能定时拉取未读回复（飞书走 lark-cli，Gmail 等网页邮箱走浏览器自动化）
   ▼
data/messages/mail.md     每行：发件人 | 内容 | 时间 | 已回复(Y/N)
   │  platforms/mail.py 的 Adapter.messages() 解析
   ▼
候选人卡片（uid 稳定去重，返回给桥服务 / 写入 data/mail.json）
```

## 消息记录格式

每条消息一行，字段固定，用 `|` 分隔：

```
发件人 | 内容 | 时间 | 已回复(Y/N)
```

- 招聘平台通知邮件（如 BOSS 直聘）发件人是统一服务邮箱、候选人姓名在主题中，发件人字段必须写成「候选人姓名 <服务邮箱>」，保证一人一卡。
- 内容最多 50 字；时间格式 `YYYY-MM-DD HH:MM`；未回复写 N，回复后改 Y。

## 候选人字段口径

- 必填字段 `uid / name / matched / bullets / weakness` 等对齐 SPEC 1.0；未知字段一律留空，**禁止编造**。
- `matched` 基础分 75（常量 `MATCHED_BASE`，邮件回复视为已触达且有意向，页面门槛默认 70），团队口径统一后可直接调整。
- uid 规则：普通个人邮件为 `mail_<邮箱>`；「姓名 <服务邮箱>」为 `mail_<姓名|邮箱散列>`（避免同服务邮箱的不同候选人被合并）；无邮箱时为 `mail_unknown_<散列>`。

## 安全与风控

- 首次使用必须先向用户确认邮箱地址并取得授权；不输入、不记录、不保存密码，遇到验证码/重新授权立即停止。
- Gmail 等网页通道依赖可正常访问邮箱站点的网络；页面打不开（ERR_FAILED/超时）时停止该通道并报告，不反复重试。
- 单次最多处理 20 条，命令/操作间隔 3-8 秒。
- 回复邮件一律先创建草稿，向用户展示并取得明确同意后才实际发送。
- **不要把真实候选人数据提交到仓库**：`data/` 下仅保留空模板。

## 本地验证

```bash
python -m py_compile platforms/mail.py
```

适配器为纯标准库实现，构造样例 `data/messages/mail.md` 后调用 `Adapter().messages()` 即可看到候选人卡片输出。
