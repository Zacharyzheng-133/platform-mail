# platform-mail 使用说明

本技能用于在邮箱上完成「登录 → 读取新消息 → 回复消息」全流程，并把每条消息按统一格式记录到 data/messages/mail.md。支持两个收信通道，流程与记录格式完全一致，按用户确认的邮箱类型选择：

- 通道 A 飞书企业邮箱：通过 lark-cli 收集，邮箱身份由平台以当前用户身份注入，全程不输入密码。
- 通道 B Gmail 等网页邮箱：通过浏览器自动化打开网页邮箱收集；首次登录必须由用户本人接管完成，AI 不代填密码或验证码。任何 Gmail 账号都适用本通道，不限于固定账号。

任何 AI 助手加载本技能后，先确认本次要收集的邮箱地址与通道，再照下列步骤操作。两个通道的消息都追加到同一个 data/messages/mail.md，由适配器按统一口径生成候选人卡片；每次收集完成后，还必须基于该文件生成一份单文件 HTML 网页报告（见「消息记录格式 · 网页报告」），供聚合消息平台网页直接展示。

## 登录
1. 首次运行前，必须先向聚合消息平台用户确认本次使用的邮箱地址、所属通道并取得授权；未经用户确认不得开始拉取邮件。
2. 通道 A（飞书企业邮箱）身份核验：运行 lark-cli mail user_mailboxes profile --params '{"user_mailbox_id":"me"}'（在 PowerShell 中内层双引号需转义为 \"），核对返回的 primary_email_address 与用户确认的邮箱地址（示例占位：your-name@example.com）完全一致；不一致立即停止并报告。
3. 通道 B（Gmail 等网页邮箱）登录态检查：用浏览器打开 https://mail.google.com/mail/u/0/#inbox，等待页面加载完成（Gmail 较重，可能需要 30 秒以上），通过页面标题或账号菜单确认当前登录账号与用户确认的邮箱一致。
4. 通道 B 出现登录页、二次验证或验证码时，立即调用 interaction.request_action（类型 browserControl）请用户本人接管完成登录或验证，AI 不代填、不记录、不保存密码与验证码；用户完成后重新观察页面再继续。若页面报 ERR_FAILED、连接超时等网络错误（通常是代理不通），立即停止该通道并向用户报告，不得反复刷新重试。
5. 全程不输入、不记录、不保存任何密码。若任一通道返回鉴权失败、登录态过期或要求重新授权，立即停止并请用户处理，不得反复重试（见「风控红线」）。
6. 非首次运行先做登录态检查：通道 A 身份有效、通道 B 能直接打开收件箱，即进入「读取新消息」；登录态失效则回到第 1 步重新向用户确认。

## 读取新消息
1. 通道 A：运行 lark-cli mail +triage --folder INBOX --is-unread --max 20 --format json，只拉取收件箱未读邮件摘要（date、from、subject、message_id）。
2. 通道 B：在 Gmail 收件箱页面只读取未读会话行——未读行可通过固定页面结构识别（未读会话行 tr.zA.zE），从中提取发件人、主题、时间列；单次最多处理 20 条，滚动加载不超过两屏，剩余留待下一次任务。
3. 两个通道都逐条判断是否为与猎头业务相关的候选人回复：招聘平台转来的应聘邮件、候选人直接回复、简历投递、约面时间等；广告、订阅、账号安全、付款、系统通知等非候选人邮件一律跳过。
4. 招聘平台通知邮件（如 BOSS 直聘）发件人是统一服务邮箱、候选人姓名在主题开头，记录时发件人字段必须写成「候选人姓名 <服务邮箱>」（示例占位：张三 <cv@service.example.com>），保证一人一卡不被合并。
5. 需要正文时：通道 A 对多个 message_id 一次性运行 lark-cli mail +messages --message-ids id1,id2,id3（只需纯文本时加 --html=false），禁止循环单封读取；通道 B 逐个点开相关会话读取正文后返回收件箱列表，不相关邮件不打开。
6. 对每条有效邮件，按「消息记录格式」追加一行写入 data/messages/mail.md，一行一条，写在文件末尾；写入前先读文件末尾已有记录，同一发件人且同一主题/时间的邮件视为已收集，不重复写入。
7. 单次最多处理 20 条，处理完即停止；每两条命令或页面操作之间间隔 3-8 秒。
8. 处理过的邮件可标记已读（可逆操作），便于下次识别新消息：通道 A 用 lark-cli mail +message-modify 批量移除 unread 标签；通道 B 在收集写入完成后勾选对应会话点「标记为已读」，或利用打开会话自动已读的机制。不删除、不移动任何邮件。
9. 收集写入完成后，运行 tools/gen_mail_report.py 由 mail.md 生成网页报告（或按「消息记录格式 · 网页报告」规范手写同等 HTML），同时产出 data/reports/mail_YYYYMMDD.html（按日留档）与 data/reports/mail_latest.html（固定文件名），再进入后续步骤。调用时必须用参数记录本次收集结果，即使新增 0 条也要记录：--log-channel 通道名（Gmail / 飞书）、--log-account 收信邮箱、--new 本次新增条数、--replied 已回复条数、--skipped 跳过通知数、--unread-total 收集时未读总数、异常时加 --anomaly、--note 备注；收集状态累积在 data/reports/collection_status.json，网页报告的「最近收集状态」区据此展示每个通道的最近收集时间、新增数与正常/异常，保证 0 新增时平台网页也能看到该通道何时收过。

## 回复消息
1. 回复一律先创建草稿、绝不直接发送。通道 A 运行 lark-cli mail +reply --message-id 原邮件ID --body 回复正文，默认只存草稿；通道 B 打开对应会话，点「回复」输入正文后关闭编辑区，Gmail 会自动保存为草稿，不点发送。
2. 正文用简洁中文，示例占位：「张三您好，感谢回复，请问明天下午方便电话沟通吗？」；候选人姓名、手机号一律用占位符（张三 / 13800000000）。
3. 必须向用户展示草稿的收件人、主题、正文摘要（通道 A 结果中带草稿打开链接时一并发给用户；通道 B 请用户在 Gmail 草稿箱查看），获得用户明确同意后才实际发送：通道 A 运行带 --confirm-send 的同一命令，通道 B 再进入草稿点发送；未经用户确认不得发送。
4. 通道 A 发送后运行投递状态查询确认已发出；通道 B 发送后确认会话中已出现该回复。
5. 在 data/messages/mail.md 中，把对应消息行的「已回复」字段由 N 改为 Y。

## 消息记录格式
每条消息记录为一行，字段固定，用 | 分隔：
发件人 | 内容 | 时间 | 已回复(Y/N)
- 发件人：写信人姓名或邮箱；平台通知邮件写「候选人姓名 <服务邮箱>」（示例占位：张三 / zhangsan@example.com）
- 内容：邮件主题或正文摘要，最多保留 50 字，超出部分用……省略
- 时间：格式 YYYY-MM-DD HH:MM，以邮件时间为准。通道 A 直接取 date 字段；通道 B 需把 Gmail 列表时间换算为该格式：只显示时分的按当天日期补全，显示「M月D日」的按当前年份补全年份，显示完整年月日的直接换算，确实没有时分的补 00:00
- 已回复：未回复写 N，回复后改 Y
- 示例：张三 | 已收到 JD，明晚可电话沟通 | 2026-09-06 09:12 | N

数据交换约定：
- 两个通道读取到的消息都写入同一个 data/messages/mail.md，每行格式同上
- 网页报告只允许写入 data/reports/ 目录；除 data/messages/mail.md 与 data/reports/ 下报告外，禁止修改其他任何文件

### 网页报告（HTML，供平台网页展示）
每次收集后必须产出与平台其他报告同风格的单文件 HTML 报告，方便接入聚合消息平台后直接在网页显示：
- 输出位置：data/reports/mail_YYYYMMDD.html（按日留档）与 data/reports/mail_latest.html（固定文件名，供平台页面直接引用）；优先运行 tools/gen_mail_report.py 由 mail.md 自动生成，保证口径一致
- 单文件、全部样式内联，不引用任何外部 CDN、网络字体或远程图片，保证离线也能打开
- 页面结构：标题「邮箱候选人回复报告（N条）」+ 元信息行（生成时间、数据来源、按时间倒序）+ 统计卡片（消息总数、候选人数去重、已回复、待回复）+「最近收集状态」区（每个通道一张状态卡展示最近收集时间/本次新增/正常或异常，下方为最近 10 次收集明细表，数据来自 data/reports/collection_status.json）+「候选人消息明细」白底圆角表格（列：#、发件人、内容、时间、状态），明细按时间倒序
- 视觉规范：页面底色 #f9fafb、内容区 max-width 1100px、卡片与表格白底圆角带轻阴影、表头 #f3f4f6；状态标签为圆角小胶囊——待回复（N）琥珀色（文字 #ca8a04、底 #fef9c3），已回复（Y）绿色（文字 #16a34a、底 #dcfce7）；候选人姓名下方用 11px 灰字展示服务邮箱
- 所有写入 HTML 的文本必须先做 HTML 转义（<、>、&、引号），防止正文内容破坏页面；没有消息时显示「暂无候选人回复消息」空状态，不编造任何记录

## 风控红线
- 禁止出现真实账号密码，网页登录与验证码一律由用户本人接管
- 遇到验证码立即停止，网络层打不开网页时停止并报告，不反复重试
- 单次最多处理 20 条
- 操作间隔 3-8 秒
